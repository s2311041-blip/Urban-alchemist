## 0. この表の読み方

| 記号 | 意味 |
|------|------|
| **needType（困りの型）** | 行 — どんな困りか。選べる解決案のセットもここで決まる |
| **planId（解決案）** | 列 — どう直すか |
| **Link / Place / Inclusive / Livability** | 島全体の満足度4軸。プラン確定時に加算（point 規模 ×1、line ×2、area ×3） |
| **予算** | セッション共有予算から減るコスト（point 基準。line/area も倍率適用） |
| **方向** | `++` `+` `0` `-` `--` — 数値を決める前の合意用 |
| **Δ（数値）** | 実装用。5段階目安: ±20 / ±15 / ±10 / ±5 / ±2 / 0 |

**満足度の変化 = needType × planId の交点**（型だけ・案だけでは決まらない）。

## 1. 4属性の定義（Link / Place / Inclusive / Livability）

| key | 名称 | 英語 | 一行定義 | 上がる典型例 | 下がりやすい典型例 |
|-----|------|------|----------|--------------|-------------------|
| `link` | 移動・効率性 | Link | スムーズかつ迅速に通れるか（通行性・移動速度） | 段差解消、案内改善、動線整理 | 迂回・工事中・混雑 |
| `place` | 滞在・賑わい | Place | 留まって楽しむ・交流できるか（快適性・滞在性） | ベンチ、広場整備、待合スペース | 立ち入り制限、スペース削減 |
| `inclusive` | 安全・バリアフリー | Inclusive | 危険や恐怖なく、誰もが安心して通行できるか | BF整備、照明、見守り、死角解消 | 放置、段差残存、夜の不安 |
| `livability` | 静穏・住環境 | Livability | 騒音・ゴミ・混雑なく、平穏に暮らせるか | 清掃・維持、ゴミ対策 | 賑わい・工事・光害・遠回り |

### 1.1 ゲージ上のルール（合意済み想定）

| 項目 | 値 |
|------|-----|
| 初期値（4属性すべて） | 50% |
| クリア下限 | 各属性 20% 以上 |
| 変動タイミング | プラン確定（DIY 完成）時。選択中はプレビューのみ |
| AR `affectedGroups` との関係 | オーブ表示・共感用。**ゲージの軸とは別**（まちの4質） |

### 1.2 熟議で押さえる対立軸

| 対立 | ゲーム上の意味 |
|------|----------------|
| **Place ↑ vs Livability ↓** | 賑わい vs 静けさ（ベンチ・拠点・イベント） |
| **Link ↑ vs Livability ↓** | 効率 vs 近隣への負担（迂回・工事） |
| **Inclusive ↑ vs Livability ↓** | 安全・照明 vs 光害・夜の静けさ |
| **Link ↑ vs Inclusive △** | 案内だけでは BF 不十分（sign_info の限界） |

## 2. 解決案一覧（planId）

Serious Mode で使用する **8種**（`transit_link` / 海列車は Serious では off）。

| planId | UI ラベル | 説明 | 主に動かす属性（素効果） | 予算目安 |
|--------|-----------|------|--------------------------|----------|
| `hard_fix` | 段差を解消する | 物理的障壁の除去・スロープ等 | Link++, Inclusive++, Livability− | 高 (8) |
| `detour_path` | 迂回ルートを作る | 通れない場所を避ける動線 | Link±, Livability− | 中 (3–4) |
| `sign_info` | 案内で誘導する | 看板・サイン・情報 | Link+, Inclusive△ | 低 (1–3) |
| `lighting` | 照明を増やす | 街灯・明るさ・死角の低減 | Inclusive++, Livability− | 中 (3–4) |
| `maintenance` | 維持しやすい空間に | 清掃・美化・ベンチ+歩道等 | Livability++, Place+ | 中 (3–4) |
| `care_point` | 見守り拠点をつくる | ベンチ+照明・人の目 | Place+, Inclusive+, Livability− | 中 (6) |
| `mobility_support` | 移動支援を導入 | バス停・乗降支援等（旧 transit 系） | Link++, Inclusive+ | 高 (9–10) |
| `ignore` | 無視する（何もしない） | 予算0・4属性ペナルティ | 4属性すべて− | 0 |

### 2.1 解決案の素効果（needType 共通・方向のみ）

| 解決案 | Link | Place | Inclusive | Livability | 熟議メモ |
|--------|:----:|:-----:|:---------:|:----------:|----------|
| hard_fix | ++ | 0 | ++ | − | 工事・景観。Inclusive は BF として説明しやすい |
| detour_path | + | 0 | 0 | −− | Link は「接続」は↑だが「効率」は↓の両論。どちらを取るか |
| sign_info | + | 0 | △ | 0 | BF 代替にならない点を Inclusive △ で表現 |
| lighting | △ | 0 | ++ | − | 光害・夜の静けさ。V/S 型で Inclusive 強め |
| maintenance | △ | + | △ | ++ | R/M 型の本命 |
| care_point | 0 | ++ | + | − | 人が集まる＝Place↑ Livability↓ |
| mobility_support | ++ | 0 | + | △ | L/C 型。Livability は停留・乗降ノイズ |
| ignore | −− | − | −− | − | 放置コスト。型によって Inclusive の落ち方を変える |

## 3. 困りの型一覧（needType）

| needType | ラベル | hint（AR） | PPS 寄り | 優先して上げたい属性 | 候補プラン（ignore 除く） |
|----------|--------|------------|----------|----------------------|---------------------------|
| **P** | 歩きにくい | 段差・狭さ | 動・Access | Link, Inclusive | hard_fix, detour_path, sign_info |
| **L** | 行き来しにくい | A↔B がつながらない | 動・Access | Link | mobility_support, detour_path, sign_info |
| **I** | 分かりにくい | 案内不足 | 動・Access | Link | sign_info, maintenance |
| **V** | 見えにくい | 暗さ・死角 | 環境・Comfort | Inclusive, Livability | lighting, care_point, sign_info |
| **M** | 汚れ・荒れ | 清掃・維持 | 環境・Comfort | Livability, Place | maintenance, hard_fix, sign_info |
| **R** | 休めない | 座る・待つ場所不足 | 静・Uses | Place | care_point, maintenance, sign_info |
| **S** | 不安・怖い | 人・雰囲気 | 社会・Sociability | Inclusive | care_point, lighting, sign_info |
| **C** | 頼れない | 助けを求めにくい | 社会・Sociability | Inclusive, Place | mobility_support, care_point, sign_info |
| **O** | その他 | 8型に当てはまらない | — | （個別判断） | sign_info, maintenance, care_point |

### 3.1 scale（規模）倍率

| scale | 意味 | Δ・予算倍率 |
|-------|------|-------------|
| point | 一点 | ×1 |
| line | 動線 | ×2 |
| area | 周辺 | ×3 |
